# 0003. 비밀번호 자동 입력은 SSH_ASKPASS 와 로컬 소켓으로 한다

- 날짜: 2026-11-13
- 상태: 채택

## 배경

접속은 시스템 OpenSSH(`ssh`)를 터미널에서 실행한다 (호환성). 그런데 OpenSSH는 명령줄 인자로 비밀번호를 받지 않는다. 비밀번호 호스트에 클릭 한 번으로 접속하려면 ssh가 비밀번호를 물을 때 앱이 대신 답해야 한다.

검토한 방법:

| 방법 | 문제 |
| --- | --- |
| 터미널 출력에서 "password:"를 찾아 자동 타이핑 | 출력 형식에 의존, 잘못 감지하면 비밀번호가 화면·원격 명령에 노출 |
| `sshpass` 같은 외부 도구 | 별도 설치 필요, 비밀번호를 환경변수·파일로 넘김 |
| SSH 라이브러리로 직접 접속 | ssh config·agent·ProxyJump 호환성을 다시 만들어야 함 |
| **SSH_ASKPASS + 로컬 소켓** | OpenSSH 공식 기능. 비밀번호가 디스크·환경변수에 남지 않음 |

## 결정

1. 비밀번호 호스트의 화면을 열 때 `SSH_ASKPASS=<도우미 스크립트>`, `SSH_ASKPASS_REQUIRE=force`(OpenSSH 8.4+)와 화면별 일회용 토큰(256비트)을 환경변수로 넣는다.
2. ssh가 묻는 질문을 도우미 스크립트가 받는다. 비밀번호 질문이면 토큰과 질문을 앱의 Unix 소켓으로 보낸다 (`/usr/bin/nc -U`).
3. 앱은 다음을 모두 확인한 뒤 Keychain의 비밀번호를 돌려준다.
   - 요청한 프로세스가 같은 사용자인지 (`getpeereid`)
   - 토큰이 살아 있는지 (화면이 닫히면 폐기)
   - 질문에 그 호스트의 주소·별칭이 들어 있는지 (점프 호스트 등 다른 서버에 주지 않음). 대상이 없는 "Password:"는 허용
4. 같은 ssh가 두 번째로 비밀번호를 물으면(저장된 값이 틀림) 스크립트가 터미널에서 직접 묻는다.
5. 비밀번호가 아닌 질문(호스트 키 yes/no, 키 암호, OTP)은 스크립트가 `/dev/tty`로 직접 묻는다. `force` 모드에서는 모든 질문이 스크립트로 오기 때문이다.

소켓·스크립트 위치: 사용자 전용 임시 폴더 `$TMPDIR/MyTerminal/` (폴더 0700, 소켓 0600). 소켓 경로는 104바이트 제한이 있어 Application Support 대신 임시 폴더를 쓴다.

## 감수하는 점

- 스크립트가 `/usr/bin/nc`와 `/bin/sh`에 의존한다 (macOS 기본 포함).
- 같은 사용자 권한으로 실행되는 악성 프로그램이 토큰을 알아내면 비밀번호를 요청할 수 있다. 토큰은 해당 ssh 프로세스 환경에만 있고 macOS는 다른 프로세스의 환경변수 읽기를 막는다. 같은 사용자 권한의 악성 코드는 어차피 Keychain 접근 요청도 할 수 있으므로 위협 모델 밖으로 본다.
- 개발 빌드는 임시 서명이라 빌드할 때마다 Keychain 접근 확인 창이 뜰 수 있다. 배포 서명(M6) 후에는 사라진다.
