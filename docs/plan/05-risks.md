# 5. 위험 요소와 대응

가장 큰 위험은 libghostty C API가 외부 앱용으로 안정화되지 않았다는 점입니다. 버전 고정과 어댑터 계층으로 영향을 한 곳에 가둡니다.

| 위험 | 영향 | 대응 |
| --- | --- | --- |
| libghostty C API가 안정화된 공개 API가 아님 | Ghostty 업데이트 시 빌드가 깨짐 | 릴리스 태그로 고정, 엔진 호출은 `GhosttyAdapter`에만 둠 |
| Ghostty가 특정 Zig 버전을 요구 | 개발 환경에 따라 빌드 실패 | 필요한 Zig 버전을 문서화하고 스크립트로 확인 |
| 한글 IME 조합 입력, 두 칸 문자 폭 처리 | 한글 입력이 깨지면 쓸 수 없음 | M1에서 조기 검증, Ghostty 구현을 그대로 이식 |
| SFTP가 터미널과 별도로 연결 | OTP·ssh-agent 환경에서 인증 두 번 | M4 전에 PoC, OpenSSH ControlMaster 재사용 검토 |
| AI의 잘못된 명령, 민감정보 전송 | 데이터 손실, 정보 유출 | 자동 실행 금지, 위험 명령 경고, 민감정보 가림, 전송 미리보기 |
| 1인 개발 일정 지연 | 공개 시점이 밀림 | 마일스톤별 완료 기준, M4·M5 범위 축소 후 v0.2로 이월 |
